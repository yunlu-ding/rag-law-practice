# 法规评测集 · 使用说明

## 这个评测集在测什么

**检索层**：给定一个问题，系统有没有把"能回答它的那段原文"召回到结果里。

不测模型说得漂不漂亮，只测**依据有没有到手**。理由：问答答错有两个原因——
没召回到，或者召回到了但模型没说对。先把这个变量摘掉，剩下才是提示词的问题。
而且检索层判据是逐字比对，**跑一百次结果一样**，不受模型采样、限流、费用影响。

## 你怎么填

工作分成三份文件，**输入和输出分开**——这一点是刻意的：
如果把"判定"和"问题"放在同一张表里，人很容易一边看答案一边改题，
最后测出来的是"模型和自己是否一致"。

| 文件 | 是什么 | 谁产出 |
|---|---|---|
| `法规评测集.xlsx` | **输入，也是唯一源**：题目、锚点、参考答案要点 | 题目和锚点已生成；答案要点和备注由你填 |
| `检索评测明细.csv` | **输出**：每题检索命中没命中 | `跑检索评测.py` 自动生成 |
| `问答评测明细.csv` | **输出**：每题的系统回答，旁边留了判定列 | `跑问答评测.py` 生成，**判定由你填** |

评测集用 **xlsx** 而不是 CSV：人编辑时 CSV 里只要有一格写着逗号或换行，
整张表的列就会串位，而且事后很难看出是哪一行错的。
脚本通过 `评测/评测集.py` 读写它，**不再有第二份 CSV**——
两份源一定会分叉，人改了 xlsx、脚本读的还是旧 CSV，跑出来的是几天前的题。

### `法规评测集.xlsx` 里你要填什么

| 列 | 谁填 | 说明 |
|---|---|---|
| 编号 / 维度 / 难度 / 问题 / 期望行为 | 已经填好 | 有问题可以直接改 |
| 依据文件 / 依据条款 | 已经填好 | 如果指错了，改这里，然后重跑 `生成锚点.py` |
| **锚点原文[待核对]** | **已自动生成，请你核对** | 见下方"锚点为什么要你核对" |
| **参考答案要点[待你填]** | **你来填** | 一个正确答案必须覆盖哪几个要点 |
| **备注[待你填]** | 你来填 | 有歧义、有疑问写在这里 |

### `参考答案要点` 怎么填——这一条最容易填错

**从原文里读出来写，不要看模型的输出。**

举例，`D4-02 违反证券法第八十八条会被罚多少钱`，你填的应该是：

> 责令改正、给予警告，处 10 万~100 万元罚款；对直接负责的主管人员和其他直接责任人员处 20 万元以下罚款

这是**考卷的答案**，由出题人写。如果拿模型输出反过来当标准，模型答错了你也会
把错的抄成"标准"，评测就永远显示满分——它测的是"模型是否与模型一致"。

判定标准建议：

| 判定 | 什么情况 |
|---|---|
| 通过 | 结论正确，且引用的条款能支撑结论 |
| 部分 | 结论方向对，但漏了要点，或引错了层级 |
| 未通过 | 结论错误，或引用了不存在的条款，或该拒答却硬答 |

### 锚点为什么要你核对

锚点是**从语料里逐字截出来的**（脚本截每条的前 36 个字），这么做是为了保证
它跟库里的文本一模一样——手工抄写时顺手改个标点，比对就会全线判为未命中，
而报告看起来像"检索坏了"。

但自动截取有个**已知缺陷：它取的是每一条的开头，而答案不一定在开头**。

实例：`D6-06 客户不配合提供适当性信息怎么办`，锚点取的是《适当性管理办法》
第三十三条的开头"投资者购买产品或者接受服务，按规定需要提供信息的，
所提供的信息应当真实、准确、完整"——**这段话没有回答"怎么办"**。
真正回答它的是同一条的后半段："经营机构应当告知其后果，并拒绝向其销售产品或者提供服务。"

所以你的核对工作主要是：**看这一题的锚点是不是真的能回答这个问题**；
不是的话，换成那几句。

## 怎么跑

```bash
# 1. 先确认语料没变（改了语料要先重新生成锚点）
python 评测/生成锚点.py

# 2. 跑检索评测（不调大模型，快、免费、结果可复现）
python 评测/跑检索评测.py

# 3. 跑问答评测（会调大模型，42 题；产出一张留了判定列的表）
python 评测/跑问答评测.py

# 只看某一个维度
python 评测/跑检索评测.py --only D7
python 评测/跑问答评测.py --only D8 --limit 6
```

**第 3 步不需要你手工去页面上问题、复制答案**——脚本会把所有回答原样跑出来
并写进 `问答评测明细.csv`，你只需要在旁边的 `人工判定[待你填]` 列里填。
之所以要这样：42 题手工搬运意味着 42 次复制粘贴，粘错一行整份结果就不可信了，
而且**人工介入得越早，越容易在不知不觉中把结果"整理"成自己期望的样子**。
人是判官，不是搬运工。

输出：`检索评测明细.csv`、`问答评测明细.csv`（都是可复查的表格）。

## 判定口径

写在代码里（`跑检索评测.py` 的 `judge` 函数），因为"命中"这个词很容易各说各话：

| 期望行为 | 判定 |
|---|---|
| `命中` | 至少命中 1 个锚点 |
| `命中至少两个层级` | 命中 ≥2 个锚点才算通过——只命中一个说明跨层级综合没做到 |
| `应拒答` / `应说明…` | **判不了，标为「待人工」** |

## 哪些事人工判不了（或者说，不该由人来判）

这是这份文档里最值钱的一段。

### 1. 拒答类的对错——**必须人判，但自动化判不了**

`D8` 那 6 题的正确答案是"没有答案"。检索层判不了它们，
**不是偷懒**：这个项目已经验证过，"检索分数低"和"语料里确实没有"是两件事
（问境外规则时，最高分并不低，因为国内法规里也提到"境外成熟市场"）。

所以这几题只能：跑问答 → 人读回答 → 看它有没有正确地说"我不知道"。

### 2. 同一问题问两次结论是否一致——**人判不可靠**

人看两段文字判断"是不是同一个结论"，本身带主观性，而且没法复现
（模型采样不可重复）。这件事**必须自动化**：同一问题跑 N 次，
比对 `结论` 字段（它是枚举值：违反/不违反/无法判断/说明）和引用的条款号，
全等才算稳定。

### 3. 拒答阈值该定多少——**人工逐题看分数是错误做法**

阈值是个统计量，应该由"标注过的问题在各分数段的分布"自动扫出来，
而不是人工逐题看。人工看 40 条得不出阈值，看 400 条也不行。

### 4. 有没有编造引用——**已经自动了**

后端在生成之后会检测"模型引用了不存在的片段编号"，不需要人复核。
评测时只要看这个计数就好。

| 维度 | 通过 | 未通过 | 待人工 | 通过率 |
|---|---|---|---|---|
| 条款精确定位 | 14 | 0 | 0 | 100% |
| 跨层级综合 | 9 | 7 | 0 | 56% |
| 概念与定义 | 14 | 1 | 0 | 93% |
| 数值与门槛 | 15 | 0 | 0 | 100% |
| 时效与效力 | 11 | 3 | 1 | 79% |
| 业务场景判断 | 11 | 4 | 0 | 73% |
| 跨业务线差异 | 5 | 10 | 0 | **33%** |
| 边界与拒答 | 0 | 0 | 15 | — |
| **合计** | **80** | **24** | **16** | **77%** |

> 这是**人工核对修正 + 文档多样性**之后的结果。修正前是 75%（78/104）。
> 具体改了什么见下面两节。

### 先说一个方法论上的收获：小样本真的会骗人

这份集子从 42 题扩到 120 题（每维度 15 题）之后，同一个维度给出了**完全不同的数字**：

| 维度 | 42 题时 | 120 题时 | 差 |
|---|---|---|---|
| 跨层级综合 | 25% | **53%** | +28 个点 |
| 跨业务线差异 | 25% | **20%** | −5 个点 |
| 条款精确定位 | 83% | 93% | +10 个点 |

跨层级综合那一栏差了 28 个点，而按 4 题的样本量算，它的置信区间本来就是 ±35%——
**这个数字从一开始就没有意义**。所以"多跑几题看看"这件事，是有具体理由的，
不是"更严谨一点"这种空话。

### 28 个失败：两个原因，都不是随机的

**原因一：一份"解释性问答"把权威条文挤下去了（14 题，正好一半）。**

未通过的题里，第一条命中是《证券期货投资者适当性管理办法》问答.pdf 的有 **14 题**。

原因不难理解：那份问答是**用口语解释法规**的，语气和用户提问最接近，
语义相似度天然占优；而法规条文写得很紧，"客户不配合提供适当性信息怎么办"
这种问法在法条里找不到对应措辞。

后果是：**用户拿到的是"解释"，不是"依据"**。而问答是规范性文件、
《适当性管理办法》是部门规章——**效力不同**。我们已经把效力层级存进元数据了，
但**排序时没用它**。

**原因二：跨文档的问题只召回了一份文件（跨业务线差异 20%）。**

D7 的 12 个失败里，除了被问答抢走头名的，其余都是"两份需要同时看到的文件只来了一份"：

| 问题 | 需要 | 实际首条 |
|---|---|---|
| 证券和基金两条线的自律管理分别由谁负责 | 上交所指南 + 中基协指引 | 只来了《适当性管理办法》 |
| 证券线和基金线对资料保存期限的要求一样吗 | 证券公司监督管理条例 + 中基协指引 | 只来了证券法 |
| 基金线和证券线的适当性匹配原则怎么表述 | 中基协指引 + 适当性管理办法 | 只来了适当性管理办法 |

原因是 top-5 会被**一份文件内部的相邻切片**占满——相似度高的切片天然聚在一起。
而"对比两条业务线"这类问题，需要的是**跨文档的覆盖**，
不是"同一份文件里最像的五段"。

这是一条明确的优化方向：**结果里保证文档多样性**（比如按文档配额，
或做 MMR 式的多样性重排），而不是单纯取相似度最高的前 K 条。

### 还有一个评测集本身的问题（我的错）

`D1-05 期货和衍生品法对适当性义务是怎么规定的` 放在"条款精确定位"维度，
但**问题里根本没出现条号**，所以条款直查不会触发——它其实是一道普通语义检索题。
维度归错了，应该挪到 D2 或 D7。类似的需要你核对锚点时一并看一眼。

## 第一轮优化：文档多样性（75% → 77%）

### 改了什么

重排是按"这一段有多像问题"排序的，而**同一份文件里相邻的切片内容高度重叠**，
于是一份文件很容易一次占满前 5 个位置。基线里 28 个失败有 14 个都是这种情况。

改动：选出结果时，**同一份文件已经选过一次的，再选就从分数里扣掉一个惩罚量**
（`RERANK_DIVERSITY_PENALTY`，默认 0.08）。前两名不动——它们是最强证据，
重复带来的问题主要在尾部。

### 中间踩的一个坑（值得记下来）

第一版改完，数字**一模一样**（75% vs 75%）。看起来像"这个改动没用"，
实际是"这个改动没生效"：`rerank(..., top_k=5)` 只返回 5 条，
而多样性处理是在这 5 条里做的——**被挤掉的正确答案往往排在重排的第 6~20 名，
代码根本看不到它**。

改成先多取（`top_k × 4`）再做多样性，结果立刻就出来了。
教训：**改完没效果，先确认改动有没有真的执行到，再怀疑方向。**

### 结果：+4 变好、−2 变差

逐题对照（惩罚取 0.03 和 0.08 的差异**完全一样**，说明不是调参调出来的）：

| 变化 | 题目 | 为什么 |
|---|---|---|
| 🟢 D1-05 | 期货和衍生品法对交易者适当性是怎么规定的 | 需要第五十条 + 第一百三十五条 |
| 🟢 D2-12 | 代销场景下适当性责任怎么划分 | 需要《办法》第二十六～二十八条 |
| 🟢 D6-02 | 最低风险承受能力类别坚持买 R5 | 换进了有明文禁止的那一条 |
| 🟢 D7-05 | 基金线和期货线风险等级划分的差别 | 需要两份文件 |
| 🔴 D5-06 | 基金募集机构指引什么时候实施 | 单文档答案被挤掉 |
| 🔴 D7-08 | 交易所和行业协会各自负责什么 | **题目本身需要同一份文件的两条**，多样性正好跟它作对 |

结论：**这是一个真实但很小的改善，而且是取舍不是白赚。** 多文档问题变好，
单文档问题会掉一点。净 +2 题。

### 它没有解决什么

**跨业务线差异仍然是 33%，基本没动。** 原因是根本性的：
那些题的**第二份文件压根不在候选池里**——重排的 100 个候选里没有它，
再怎么调排序也召不回来。

所以"对比两条业务线"这类问题，正确的解法不是排序，而是**查询拆分**：
把"证券和期货有什么不同"拆成两次检索再合并，让每一条业务线各自去召回自己的依据。
这是在"检索之前"做的事，不是"检索之后"。

## 第二轮尝试：查询拆分（三次都没成，结论比结果重要）

### 三次尝试与数字

| # | 做法 | 结果 |
|---|---|---|
| 0 | 不拆（多样性已开） | 77%，跨业务线 **33%** |
| 1 | 拆成"业务线名 + 原问题"，只用来扩候选池 | 77%，33%（**没变化**） |
| 2 | 再加"每条业务线保底一个位置" | 77%，33%（**没变化**） |
| 3 | 把子查询改成真正的单业务线问法，仍保底 | **76%**，27%（**更差**） |

### 每一次"没变化"背后都有一个具体原因

**第 1 次**：以为"第二个业务线不在候选池里"。诊断发现**它在**——
结果来源标记里能看到 `vector·证券`、`bm25·期货`。真正的问题是**重排**：
它给《问答》里泛泛而谈的段落 0.37 分，给《证券法》第八十八条、
《期货和衍生品法》第五十条只有 0.15。

这**不完全是重排的错**：没有哪一段单独回答了"两者有什么区别"，
交叉编码器给"部分相关"打低分是合理的。

**第 2 次**：加了保底之后，第 1、2 名确实变成了 `coverage·证券` 和 `coverage·期货`——
但**两条保底选中的是同一片**（《问答》的开头）。
因为子查询 "期货 证券和期货在适当性义务上的法律规定有什么区别"
**里面还有"期货"两个字**，两条子查询问的还是同一件事。

**第 3 次**：把子查询改成真正的单业务线问法（"证券在适当性义务上的法律规定"），
保底终于选中了不同片段——**但数字更差了**。
强行给每条业务线塞一个位置，会挤掉本来更相关的内容。

### 结论

**对比类问题是这套检索架构的固有短板，规则化的拆分和保底都救不了它。**
三次尝试，一次没效果、一次没效果、一次更差。

原因不难理解：这类问题要的**不是"找到最像的几段"，而是一份"两边的对照"**——
而对照本身在语料里不存在，得有人（或模型）把两边读完之后写出来。

**这恰好就是 Wiki 那一层要做的事。**

所以这条失败不该继续在检索层打补丁，而应该作为**引入 Wiki 的论据**：
它说明"预编译的、跨文档的综合"有明确的需求场景，
而且现在有一个可量化的缺口（跨业务线差异 33%）可以证明 Wiki 补上了多少。

代码保留但**默认关闭**（`QUERY_SPLIT_ENABLED=false`）——
未经验证、还要多花两次向量化的改动，不该成为默认值。

## 第三阶段：Wiki 通道（33% → 80%）

查询拆分三次失败之后，结论是：对比类问题要的**不是"找到最像的几段"，
而是一份"两边的对照"——而对照本身在语料里不存在**。这正好是 Wiki 那一层做的事。

于是按这个缺口选题：先 3 条（证券/期货适当性、三条线投资者分类、处罚对比），
再按评测暴露的缺口补 9 条主题，共 12 条索引型词条。

词条不是"生成"的，是**编译**的：给定主题 + 指定条款 → 取出原文 → 交给模型组织
→ 要求逐条给出依据 → **拿依据回库逐字核对**。核对不过的词条不许参与作答。

### 阶段数字

| 阶段 | 总体 | 跨业务线差异 |
|---|---|---|
| 120 题基线 | 73% | 33% |
| 人工修正锚点 + 文档多样性 | 77% | 33% |
| + Wiki（3 条词条） | 79% | 47% |
| + 补 9 条主题 | 80% | 53% |
| + 修路由（触发词 / 虚词 / 对比词） | 81% | 60% |
| + 语义路由 | 81% | 60% |

⚠️ 上表里 77% 之前是本文档先前记录过的；79%~81% 这几步是本阶段实测，
但**下面这一轮才是唯一有完整证据链（对照实验 + 敏感性检验 + 逐题归因）的重测**。

### 一个反常现象：路由命中从 10 涨到 13，通过率一动没动

语义路由上线之后，路由命中数确实涨了，但评测数字**完全没变**（81% / 60%）。

"命中变多但结果不变"只有两种可能，而它们要做的事完全相反：

- 路由送对了，是**词条没覆盖**锚点 → 该补词条；
- 路由**送错了**词条 → 该改路由。

光看通过率这两种长得一模一样，所以必须把中间那一步摊开。为此写了
`工具/诊断词条路由.py`：每个问题 → 实际路由到哪条 → 该路由到哪条 →
该中的那条词条依据里有没有评测锚点。

摊开之后，三道题卡在三件不同的事上（这就是为什么必须逐题看）：

| 题 | 现象 | 根因 |
|---|---|---|
| D7-08 / 14 / 15 | 门就没过，压根没路由 | 门的判据写成了"点名 ≥2 条业务线" |
| D7-09 / 12 | 路由到了**错的**词条 | 词条标题是"通用枢纽" |
| D7-02 | 没有对应词条 | 选题漏了（冷静期这个主题没写） |

## 第四阶段：门的判据与混合路由（81% → 84%）

### 结论一：相似度**不能**用来判"该不该走词条"

先否掉了一个看起来很自然的想法——"拿相似度当门，够了就路由"。

把 120 题全跑一遍词条相似度，得到：

    最高分是 D3-05 的 0.926 —— 而它是一道单选题，跟词条毫无关系；
    对比题这边，最低的 D7-07 只有 0.486。

**两边的分布完全重叠，方向还反了。** 所以相似度只有资格当"过了门之后，
哪条词条更像"的判据，没资格当"该不该走词条"的判据。门必须是**形状判据**。

### 结论二：门的判据要的是"多个对象"，不是"多条业务线"

原来的门要求"问题里点名 ≥2 条业务线"。这是从查询拆分那边留下来的**代理判据**，
它漏掉了三类真实问法：

    D7-08  交易所和行业协会在适当性管理里各自负责什么
    D7-14  证券和期货两条线谁负责制定产品风险等级名录
    D7-15  三条业务线在最低风险承受能力类别的认定上有什么异同

这三句都是标准的对比/分工题——它们的答案同样不存在于任何单一片段里——
但 `detect_lines` 一条业务线也认不出来，于是门直接关掉。

改法：门的第二条判据放宽成"**点名 ≥2 条业务线，或出现了多对象的说法**"
（业务线 / 条线 / 各自负责 / 分别由谁 / 谁负责 / 归谁管）。

为什么不干脆把这条删掉：删掉之后 `一样吗` / `分别` 这类通用词会单独放行
D8-04「香港证监会对专业投资者的规定和内地一样吗」——那题的正确答案是拒答，
送一条内地词条过去正好把它带偏。**要补的是"多对象"这个信号，不是取消它。**

### 结论三：路由要"语义定位 + 关键词裁决"两段

对照实验（`评测/_路由策略对照.py`）在同 14 道上比了六种打法：

| 打法 | 选对 | 说明 |
|---|---|---|
| 标题 + 触发词拼成一句（现状） | 11/14 | |
| 标题和触发词分开算、取最高 | **9/14** | **假设被否** |
| 只看标题 | 8/14 | |
| 只看触发词 | 11/14 | |
| 只用关键词 | **13/14** | |
| **混合（语义分 + 触发词命中加成）** | **14/14** | 采用 |

两条被数据打回来的判断，值得单独记：

**① "拆开算、取最高"更差。** 直觉是"标题里混了通用词，稀释了触发词"。
实测 79% → 64%。原因是**标题本身就是那个通用枢纽**
（「证券、期货、基金三条业务线的投资者分类制度对照」），取最高反而让它独占。

**② "关键词这条路修不好"是错的。** 这句话原先写在代码注释里。真实情况是：
那三次失败时，触发词写的是大词、虚词、对比词；触发词重写之后，
纯关键词拿到 13/14，比纯语义的 11/14 **还高**。
**"关键词方法不行"和"词表写得不行"是两件事**，当时把后者的锅甩给了前者，
代价是多绕了一整轮。

混合为什么有效：**语义负责粗定位，关键词负责在相邻的词条之间裁决。**
主题相邻时向量分不开——"违反适当性义务的行政处罚"和"证券与期货适当性义务对照"
本来就近；而"行政处罚""销售人员管理"这种具体主题词**逐字出现在问题里**，
是比向量相似度更硬的证据。

### 敏感性检验：这个 +3 不是调参调出来的

加成系数从 0.0 扫到 1.0：

    系数      0.00   0.01~0.03   0.05 ~ 1.00
    选对      11/14   13/14       14/14

0.05 到 1.0 是**一段 20 倍的平坦区间**，取中间任意值结果都一样。
和文档多样性那次一个是同一个道理（0.03 和 0.08 结果完全相同）：
平坦区间宽 = 结果来自结构，不是来自调参。取 0.10 是因为它在区间内偏中。

### 本轮结果

    合计            通过 87 ｜ 未通过 17 ｜ 待人工 16 ｜ 通过率 84%
    跨业务线差异     通过 12 ｜ 未通过  3 ｜ 通过率 80%（原 60%）

净 +3 题（D7-08 / D7-09 / D7-15），**其余七个维度一个没掉**。

### 三条还没过的，都不是路由问题

| 题 | 根因 | 怎么收 |
|---|---|---|
| D7-04 | 锚点含"上交所指南**首段**"，编译时被标成"该条不存在"而丢失 | 补依据或改锚点 |
| D7-06 | 词条引的是《办法》第七条，锚点却取《证券法》89 条 | 词条选题边界与锚点不一致 |
| D7-12 | `penalty-comparison` 的 `compiled_from.sources` 显示**只喂进去 3 条**，提纲写了 5 条 | 重编词条 |

这三条的价值在于：**它们证明"路由修好了"和"这类问题能答了"是两件事。**
路由 14/14 之后剩下的缺口，全在词条的选题与依据覆盖上——
那是**内容工程**，不是检索工程。

## 第五阶段：拒答判据（阈值只管一条路）

### 改之前的三个问题

原来是"拿最高分跟阈值比"一条判据管全部。实测下来它有三个毛病：

**① 分数管不了"有没有"这类问题。** 问"《适当性管理办法》第八十条"——
这部办法只有 43 条，答案是**确定的不存在**。但阈值给出的说法是
"最高分 0.31，低于阈值 0.5，相关度不足"，把确定的事实说成了模糊的猜测。

**② `score` 是混合量纲。** 翻日志能直接看到：2026-09-29 欠费那天，
向量路挂掉、只剩 BM25，同一条查询的 `score` 从 **0.32 变成 47.87**，
而它在日志里和正常记录长得一模一样。阈值 0.5 会让
**"系统最坏的一天"恰好变成"闸门最松的一天"**。

**③ 四种拒答混成一句话。** "系统故障 / 库里没有这一条 / 一条都没召回 /
分数不足"，用户看到的都是"相关度不足"，但该做的事完全不同
（重试 / 补法规 / 确认入库 / 换个问法）。

### 改之后：确定性的先判，分数的最后判

    1. 系统故障           → 拒，明确说"是系统坏了，不是资料没有"
    2. 条款直查查不到      → 拒，确定性的"库里没有这一条"
    3. 条款直查查到了      → 答，**不经过阈值**（最硬的依据）
    4. 词条命中           → 答，**不经过阈值**
    5. 一条都没召回        → 拒
    6. 混合检索分数不足    → 拒，**这才是阈值唯一该管的情况**

第 6 条还带一个附加条件：**只有重排分可用时才用阈值**。
重排不可用时分数不是标定时的那个量纲，系统进入降级模式、
在答案里标注"本次未启用重排"，绝不拿别的量纲硬套。

判据做成纯函数（`app/rag/refusal.py`），因为纯函数可以被一条条钉住：
`工具/自检拒答判定.py` 10 条用例，**10/10 通过，不联网、不连库**。

### 阈值标定：从分布里量，不用评测通过率反解

`工具/标定拒答阈值.py`，三条纪律：**只统计重排分**（混合量纲不能混着算）、
**只统计当前语料**（历史阶段的数据属于另一套语料）、
**没有负样本就说算不出来**。

一开始日志里 482 条只有 **3 条**属于当前语料——因为跑评测都刻意
`persist=False`（评测不该污染生产日志），UI 上只真问过几次。
所以冷启动跑了一次探针（11 条该拒 + 6 条该答），之后靠日志漂移看阈值要不要动。

### ⚠️ 最重要的一个实测结论：单靠一个分数分不开这两类

探针的两个分布是**重叠**的：

    该拒：0.084  0.094  0.129  0.169  0.170  0.171  0.207  0.293  0.299  0.435  0.557
    该答：0.196  0.375  0.509  0.574  0.748

具体说：

    "香港证监会对专业投资者怎么界定"（该拒）      0.293
    "基金指引什么时候实施"（该答）                0.196   ← 该答的更低
    "给我推荐几只适合现在买的基金"（该拒）        0.169
    "冷静期是什么意思"（该答）                    0.140   ← 该答的更低

所以在真实评测集上回放，阈值每调大一档，收益和代价是：

| 阈值 | 拒对无关题 | 误伤"该答" | 误伤评测里判通过的题 |
|---|---|---|---|
| 0.13 | 3/11 | 0/5 | **0/87** |
| 0.18 | 6/11 | 0/5 | 5/87 |
| 0.20 | 6/11 | 1/5 | 10/87 |
| 0.30 | 9/11 | 1/5 | **21/87** |

**结论：阈值取 0.13。** 判据是**零误伤**——评测里 87 道判"通过"的题，
最低分是 0.140，阈值不超过它就不会拒掉任何一道本来答对的题。
它只负责挡住离题最远的三条（怎么做红烧肉 0.084、明天天气 0.094、写诗 0.129）。

剩下的该拒情况**分数管不了**，必须靠各自的确定性判据：
条号不存在（已做）、境外法域（未做）、生成类任务（未做）——
最后两项是**已知缺口**，写在这里以免被"阈值已经标定好了"这句话盖过去。

### 评测集本身的读数变了

`跑检索评测.py` 从这一轮起多输出两列：**最高重排分**和**分数来源**。
理由很实际：调阈值时不必再单独跑一次评测，拿现成的表算一下就行；
而且"哪些题是走条款直查的"一眼可见——那些题本来就不归阈值管。

## 第六阶段：补词条依据（84% → 86%，跨业务线差异 80% → 93%）

第五阶段结束时，"跨业务线差异"还剩 3 道没过。逐条查过之后，**三道题的根因完全不同**，
而且其中一道根本不是我们这边的错。

### 一、三道题的三种根因

| 题 | 表面现象 | 查清之后的根因 |
|---|---|---|
| D7-06 | 路由对了，锚点没被覆盖 | 词条只用了部门规章和自律规则，**漏掉法律层级**的分类条款 |
| D7-12 | 同上 | 词条只覆盖了"法律 + 部门规章"两层，**漏掉行政法规**层 |
| D7-04 | 命中 1/2 个锚点 | **评测判据的限制**，见下 |

### 二、补词条依据（D7-06 / D7-12）

两条词条的提纲各补了来源，重编、重核、重跑：

    投资者分类对照  += 证券法第八十九条、期货和衍生品法第五十一条
    适当性后果对照  += 证券公司监督管理条例第八十四条、期货交易管理条例第六十六条

补的过程里发现**一个数字之差就是另一件事**，所以这两条是对着原文挑的：

    证券条例 第八十三条 → 客户招揽、投资建议、代客买卖        ← 与适当性无关
    证券条例 第八十四条 → 未按规定了解客户身份财产与收入状况、
                          推荐的产品与客户情况不相适应……      ← 适当性违规
    期货条例 第六十六条 → (一)接受不符合规定条件的单位或个人委托 ← 适当性违规
    期货条例 第六十七条 → 欺诈客户（作获利保证等）             ← 与适当性无关

### 三、⚠️ 修正了一处评测锚点错误（D7-12）

D7-12 原来写的依据是《证券公司监督管理条例》**第八十三条**。把原文调出来看，
八十三条列的五项是：委托他人招揽客户、提供确定性投资建议、代客买卖、
自营/资管投资范围违规、资管单笔委托低于限额——**没有一项是适当性**。
真正对应适当性的是**第八十四条**（了解客户身份财产经验风险偏好、
推荐与客户情况相适应、讲解规则并揭示风险、签订合同）。

所以这一处**是评测集写错了，不是系统答错了**。改动与审计：

* 改前先备份 xlsx；
* 只改 D7-12 的「依据条款」和「备注」，重跑 `生成锚点.py --apply` 重算锚点；
* **改后逐单元格比对 120 行**——结果只有 D7-12 的 3 个单元格变了，
  其余 119 行逐字节相同，参考答案要点一个字没动。

改评测集是危险动作（很容易变成"改考卷以适配答案"），所以判断标准写在备注里，
而且可复核：**八十三条的原文里找不到适当性**。

### 四、D7-04 不是产品的问题，是判据的限制

D7-04 的第二条锚点取的是《上海证券交易所会员管理业务指南第1号》的**首段**。
它没有条号，所以检索层的"锚点是否被词条依据覆盖"这条判据**对它失效**——
`article_int('首段')` 是 None，词条再怎么写也覆盖不到它。

这一条留在那里，作为已知限制，不为了把数字做上去而改判据。

### 五、补的过程里撞出来的两个真问题

**① 一条内容正确的词条，被排版噪声判成了"不可信"。**

`securities-vs-futures-suitability` 的 `citation_verified` 一直是 False。
查下来是《证券法》第八十九条被分页切成两片：

    chunk 101：……证券公司不能证明的，应当承担相应的—５１—
    chunk 102：赔偿责任。

模型引用的是**完整的那一句**，它引对了；但页码横在句子中间，逐字比对必然失败。
于是修 `verify_originals`：比对前先去掉**分页噪声**（页码、公报页眉）。
注意去掉的只是噪声，**底线（每个字都能在原文里连着找到）没有放松**。

顺带加了 `工具/维护词条.py --reverify`：改了校验规则之后，
已有词条要按新规则重跑一遍。**词条的 `citation_verified` 是编译那一刻算出来写死在库里的**，
没有这个入口，改进过的校验规则对老词条永远不生效。

**② 文档承诺的保证，和代码实际做的事差了一个条件。**

`wiki_route.py` 的模块说明一直写着"只路由 `citation_verified=True` 的词条"，
而代码里 `select` 的条件只有 `status == 'reviewed'`。
后果是：**一条引错了原文的词条，只要被标成 reviewed 就能参与作答**——
而它给出的是一条"看起来有依据"的结论，用户没有办法核对。

这不是假想的风险：上面那条 False 的词条，当时就是 `reviewed` 状态。
修法是补上 `citation_verified.is_(True)`。

    合计          通过 89 ｜ 未通过 15 ｜ 待人工 16 ｜ 通过率 86%（原 84%）

D7-06 和 D7-12 都翻转，**其余七个维度一个没动**。

## 第七阶段：问答层评测（第一次跑通）

### 一、这个脚本有两个 bug，所以它从来没跑成功过

"问答层没跑过"这件事，之前一直当成"还没排到"。真去跑才发现是**跑不起来**：

1. `pick(row, "编号")` —— `pick()` 只认 `code` 这类键名，第一题打印时就 `KeyError`；
2. 更贵的一个：结果只在**全部跑完之后**才写 CSV。第一次跑到第 110 题，
   撞上 `_refusal_message` 里的一个 `NameError`（我新加的拒答分支用了没导入的常量），
   **前 110 题花掉的模型调用费和结果一起没了**。

两个都修了：前者改 `pick(row, "code")`，后者改成**每题落一次盘**。
用一点 IO 换"崩了不丢钱"，这笔账没有犹豫的余地。

(顺带说明为什么 `_refusal_message` 的 `NameError` 前 110 题没暴露：
那个分支只有"解析出条号但库里没有这一条"才会走到，
而前 110 题里一道这种情况都没有——**它一直活到 D8-06**。)

### 二、跑出来的机械统计

    总题数 120
    依据强度：条款直查 15 ｜ 词条 15 ｜ 重排 87 ｜ 无依据 3
    拒答：确定性拒答 3（条号不存在）｜ 模型自拒 7 ｜ 未拒 110
    编造引用（模型引了不存在的片段编号）：**0 例**
    答案没有任何引用的：12 条（= 10 条拒答 + 2 条见下）
    结论字段不符合枚举契约：4 条（内容是对的，是**字段放错了**）

### 三、几个只有跑过才知道的现象

**① 确定性拒答真的生效了。** D8-06 / 07 / 08 问的是不存在的条号
（《适当性管理办法》第八十条、《证券法》第三百条、《创业板投资者适当性管理办法》第三十条），
三道全部被 `citation_missing` 拦下，理由写明"已识别到该条，但知识库里没有收录"。
这在旧的分数闸门下一个都拦不住——它们的重排分并不低。

**② 但是"是否拒答"这个布尔值不足以判边界题。** D8-01（美国 SEC）和 D8-02（欧盟 MiFID II）
的 `结论` 字段写的是"说明"、`refused=False`，看起来像"该拒没拒"；
可它们的理由原文是"知识库中没有关于……的信息"——**实质上是拒答**，
只是没落到 `无法判断` 这个枚举值上。

也就是说：**边界题的判定不能只看标志位，要看理由里到底说了什么。**
这一条直接影响了北极星指标怎么算——"拒答正确率"如果按标志位统计，会被系统性低估。

**③ 提示词的枚举契约不稳定。** 有 4 道题（D2-11 / D3-06 / D4-11 / D4-13）的 `结论`
字段里填的是**答案本身**（"经营机构"/"不能"/"有"/"24小时"），而不是
`违反 / 不违反 / 无法判断 / 说明` 之一。理由部分都是对的，是字段放错了位置。
4/120 ≈ 3%，而且**它是静默的**——代码只记了一条 warning，用户看到的是一个
填了答案的"结论"栏。

### 四、这一层能给出什么、还缺什么

能给的（都是机械可算的）：依据强度分布、编造引用数、拒答分因统计、
耗时与 token。

缺的（必须人来判）：

* **结论正确性** —— 对照 `法规评测集.xlsx` 的「参考答案要点」；
* **引用是否支撑结论** —— 引了 5 条不等于这 5 条撑得住结论。

这两样合起来才是北极星"可信回答率"。所以答案落在
`评测/问答评测明细.csv`，`人工判定[待你填]` 留给人。

### 五、判卷完成：北极星出来了，以及两个必须一起写出去的前提

判卷结果：**120 题全部通过**。用 `工具/统计问答评测.py` 可复现（编码自动识别：
表格给人判，人会拿 Excel 打开，一存就变 GBK，所以读的时候
按 utf-8-sig → utf-8 → gb18030 依次试，而不是写死一个）。

    北极星  可信回答率 =（结论正确 且 引用支撑结论）÷ 总回答数
                      = 120 / 120 = 100%

    过程层  依据强度：条款直查 15 ｜ 词条 15 ｜ 重排 87 ｜ 无依据 3
            编造引用（模型引了不存在的片段编号）：0 例
            答案没有任何引用的：12 条（10 条拒答 + 2 条见下）

#### ⚠️ 前提一：这个 100% 是自评的，而且一条备注都没有

判卷由**建设者本人**完成，120 题里**没有任何一条写了备注**。

这两件事单独看都不算错，合起来就说明一件事：**这个数字的置信度，
比检索层那个 86% 低**。检索层的判据是锚点逐字比对，机器算的、可复现；
这一层是"人读了觉得对"。**自己判自己的卷子，天生有偏。**

所以写进任何材料时都必须带上这句话，不能只放一个 100%。
（真正能提高它置信度的做法是找第二个人盲判一批、看两边的分歧率。
这个还没做。）

#### ⚠️ 前提二：拒答那一层给出的数字不一样，原因是"标志位"

按**系统标志位**统计：

    拒答正确率  8 / 10 = 80%
    过度拒答率  2 / 110 = 1.8%

差在哪：D8-01（美国 SEC）和 D8-02（欧盟 MiFID II）的标志位是"未拒答"，
但它们的理由原文写的是"**知识库中没有关于……的信息**"——**实质拒答了**，
只是没落到 `无法判断` 这个枚举值上，而是落在了 `说明`。

反过来 D8-09（写整改方案）和 D8-12（写风险提示邮件）被拒答了，
而评测集里它们的期望行为写的是"应说明……"。系统选了拒答——
从合规产品的角度这是可以接受的（不替用户编方案），但**输出形状和期望不一致**。

所以 100% 和 80% 不矛盾，它们量的是两件事：

* 100% 是"**答案的内容对不对**"（人读出来的）；
* 80% 是"**输出有没有落进约定的枚举值**"（机器读出来的）。

**后者才是真问题**：它意味着"结论"这个字段**不能直接被下游依赖**。
同一批回答里还有 4 题（D2-11 / D3-06 / D4-11 / D4-13）把**答案本身**
填进了"结论"栏（"经营机构""不能""有""24小时"）。加起来 6 题，
占 5%，而且全都是**静默的**——代码只记一条 warning，用户看到一个填了答案的"结论"栏。

这件事的下一步很清楚（本轮没做）：把结论字段的取值做成**后端校验 + 兜底**，
而不是指望提示词每次都听话。现在它只是一个被记录下来的现象。
